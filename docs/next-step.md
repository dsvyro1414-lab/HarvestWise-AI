# Next Step: Prove the Gemma Flow

## Recommendation

The next highest-value task is to make one live Gemma interaction unmistakable in the hackathon demo and record evidence of it. The action engine and simplified UI are complete; the remaining judge question is whether Gemma is genuinely useful and safely integrated.

Do **not** add another dashboard section before this proof path is working.

## Production Progress — 2026-07-10

Production is live at <https://harvestwise-ai.vercel.app> with encrypted `GEMINI_API_KEY` and `GEMMA_MODEL` variables.

Verified in the public UI:

- `Gemma extracted` appeared after a real model-backed farm-note request.
- `Gemma interpreted the change` appeared for `fertilizer cost rises by 20%`; deterministic profit changed from `₦680,000` to `₦654,000`.
- `Gemma explanation · deterministic decision` appeared after a real explanation request.
- Provider failures remained labelled as fallback instead of being presented as Gemma output.

The clean scenario evidence is saved in `docs/screenshots/` and embedded in the README. Extraction and explanation were also verified directly in the production browser.

Reliability hardening is deployed:

- SDK-native retries cover transient Gemini `500 INTERNAL` responses.
- backend ESM imports use explicit `.js` extensions for Vercel Node Functions.
- Gemma uses a strict single-object JSON prompt without unsupported response-schema enforcement.
- malformed, incomplete, or oversized advisor output is rejected and shown as honest fallback.

The final clean production check showed a concise explanation under `Gemma explanation · deterministic decision`. The remaining optional evidence polish is a dedicated explanation screenshot or a 30–60 second recording; the README currently embeds the clean scenario proof.

## Why This Comes Next

- The farmer-facing decision is now deterministic, prominent, and tested.
- The UI no longer hides the main action among charts and cards.
- Gemma's boundary is correct in code, but the first screen honestly shows an optional/fallback explanation until a live request succeeds.
- A short visible proof of extraction, scenario interpretation, and explanation demonstrates both the AI capability and the safety boundary.

## Scope

1. Configure a valid `GEMINI_API_KEY` for the deployed demo.
2. Start from the default maize plan.
3. Open **Import a farm note with Gemma** and use a prepared note.
4. Confirm that the UI names the successful provider as `Gemma extracted` and that the Recommended next action updates through the deterministic domain layer.
5. Open **Test a change to this plan** and run `what if fertilizer cost rises by 20%?`.
6. Confirm that the UI names the provider as `Gemma interpreted the change` and that profit/action recalculate locally.
7. Ask Gemma to explain the result and show the label `Gemma explanation · deterministic decision`.
8. Capture the three states as a 30–60 second recording or 3–4 screenshots for the README and submission.

## Acceptance Criteria

- A real model response is visible at least once for extraction, scenario parsing, and explanation.
- The action remains generated by `buildFarmerAction`, not by model text.
- The UI distinguishes `gemma` from `local-fallback` honestly.
- A missing key or failed request leaves the demo usable with local fallback.
- The public README or submission has visual evidence and a concise judge script.
